Project workspace: layout mockups

These accompany docs/design/project-workspace.md, and its rules in docs/design/model-rules.md, which the R numbers refer to. All four screens show the review's rover model under the proposed design. A, B and C follow the successful path; D shows a recovery.

  • The project tree is on the left.
  • The viewport is in the middle, with a caption, a selection filter bar and a docked legend.
  • The inspector is on the right.
  • Checks, Log, Run and Table share a dock under the viewport.

The numbers are the same in each screen. The geometry is schematic.

A · Mesh stage: reviewing a shell-mesh candidate before committing it

The chassis is idealized as shells: nine sheets were extended and joined, and the original solid is kept hidden as a reference. Paved, at size 5, produced a candidate. Nothing enters the model until Add to model.

D · Parts stage: Replace source, with one region to repair

The chassis is replaced by a revised file in which the rear-right motor holes have moved 30 mm along the wall. This is scenario S3 in the rules. Nothing changes until commit. The preview shows each region's match outcome and what follows from it. The analyst can repair the one lost pattern now, or commit with its mount suspended.
